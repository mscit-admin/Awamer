# RBAC Authorization Matrix

The matrix is derived **from code**:
- `backend/src/domain/permissions.ts`, specifically `BUILTIN_ROLES`. The matrix below was generated by
  importing that module, not by reading documentation.
- The route gates (`requirePermission`, `requireRole`, `can()`).
- The route-level tenant and target guards.

The locked built-in roles are rewritten from this code catalog on every startup
(`RoleService.syncBuiltins()`). The client gates the UI from the server-sent effective
`user.permissions`; the **server** is the enforcement point.

¹ **Target ceiling (new, SEC-TARGET-CEILING-001):** the actor may act only on a user whose
*current* permission set is a subset of the actor's own. An admin can therefore no longer
reset, disable MFA on, lock, edit, delete, demote or move a co-located super_admin, or any
user holding a permission the admin lacks.

² **Grant ceiling (pre-existing, verified):** an actor can grant only permissions or roles
contained in its own set. Global-only permissions also require super-admin.

³ **Changed in this closure.** Before, any company admin could change these
installation-wide settings (SEC-INSTANCE-001).

## 3. Observations (not vulnerabilities)

- **Some gates use role names instead of permissions.** `/admin/*` user administration,
  tunnel `bind_public`, and backend VPN connect check the role *name* (admin/super_admin).
  This fails closed: a custom role holding `users:manage` sees the Users page but gets
  403. It departs from the CLAUDE.md convention. Recommendation: move these to
  `requirePermission("users:manage")` once the target-ceiling check is in place, which it now is.
- **Readonly/auditor can write notes and session history.** They can create, share and
  delete their own notes and session-history rows (`routes/notes.ts`,
  `routes/sessionRoutes.ts` have no `requireWrite`). These are personal artefacts, not
  inventory, but this contradicts the readonly description. Tracked in `REMAINING_RISKS.md` (R-09).
- **`useCan` fails open in the UI** when no permission list is present. This is presentation
  only; the server enforces.
